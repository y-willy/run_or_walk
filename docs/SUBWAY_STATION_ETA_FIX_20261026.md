# 지하철 위치 정보가 ETA로 연결되지 않는 문제 수정

사용자 승인에 따라 기존 작업 브랜치 `83ce1ba`까지 main에 병합·push한 뒤, 정류장 찾기부터 화면·백그라운드까지의 ETA 연결을 추가 수정했다. Worker 코드·Secret은 변경하지 않았다.

## 확인한 차단 조건

1. MainActivity의 시간표 분석 효과가 `subwayDirectionRoute == null`이면 즉시 종료했다. 목적지 경로 검색에 실패하거나 역만 선택한 경우, 공식 위치를 받아도 시간표 계산은 실행되지 않았다.
2. 백그라운드 서비스 역시 지하철 경로 객체가 있어야만 시간표를 분석했다.
3. 열차 선택 버튼은 양수 실시간 ETA만 허용해 위치·시간표 추정이 가능한 열차도 선택할 수 없었다.
4. 일부 위치 추정 분기는 RAW_FIELDS만 허용해, 사용자가 처음 배포한 Worker의 stationId/lineId/receivedAt 별칭 응답을 제외했다.

## 수정한 연결

- 정류장 찾기는 카카오 경로 객체 없이도 공식 stationId·lineId·상하행·행선지와 해당 운행일의 공식 정차 순서를 사용한다.
- 정확한 공식 ETA가 있으면 우선한다. 없으면 마지막 위치와 실제 역간 시간표로 범위를 계산한다. 위치를 연결할 수 없으면 다음 공식 시간표 운행을 명시적으로 구분해 표시한다.
- 열차 위치·시간표 추정은 분 단위 범위로 표시한다. 존재하지 않는 초 단위 정확도를 만들거나 전역 개수에 고정 시간을 곱하지 않는다.
- 방향 선택 전에는 방향별 도착시간을 함께 보여주고 임의로 하나를 걷기 판단에 넣지 않는다. 목적지 또는 방향 선택 후에는 같은 계산 결과를 도보 판단과 백그라운드에 연결한다.
- 시간표로 ETA가 계산된 위치 전용 열차도 선택할 수 있다. 실시간 API 행이 없을 때는 시간표 운행 자체를 방향 선택 항목으로 표시한다.
- 같은 노선의 목적지 역은 공식 시간표 정차 순서로 직접 연결할 수 있다. 환승 등이 필요하거나 하나로 확정할 수 없으면 기존 경로 조회를 사용한다.
- 기존 Worker 별칭 응답도 명시된 위치·역·노선·방향·시각을 대조해 추정에 사용한다. 제공되지 않은 열차번호·공식 ID는 생성하지 않는다.

## 검증 결과와 한계

- 제공된 망포역 보관 JSON을 **2026-10-25 22:55:58.715 한국 시각**으로 재생: 경로 없이 하행 `약 4~7분 후`, 상행 `약 9~13분 후`의 위치·시간표 기반 추정을 얻었다. 현재 시점의 실시간 도착시간이라는 의미가 아니다.
- 동일 JSON을 예전 Worker의 별칭 필드만 남긴 형태로 재생해도 열차번호 없이 분 단위 추정이 생성됐다.
- 1호선은 포함된 공식 시간표에 관측을 구성해, 열차번호·경로 없이 숫자 ETA와 도보 판단으로 연결되는지 확인했다. 실제 최신 HTTP 응답 검증과 구분한다.
- 선택 방향이 있으면 역만 선택한 상태와 백그라운드 모두 해당 방향의 ETA를 사용했다. API 응답이 비어 있어도 유효한 다음 시간표를 표시했다.
- 기존 버스·지하철·보행·알림 회귀 검증을 포함해 임시 검증 90개 통과, 실패·오류 0개. `:app:compileDebugKotlin`, `:app:assembleDebug` 성공.
- 테스트 코드·추가 테스트 의존성은 저장소에 넣지 않았다.
- 연결된 실기기가 없어 새 APK의 지도·실시간 수신·화면 꺼짐 알림은 직접 확인하지 못했다. 시간표에 해당 노선·요일·정차 경로가 없거나 운행이 끝나 유효한 예정 운행이 없을 때는 시간을 임의 생성하지 않는다.

적용에는 최신 main으로 APK를 다시 빌드·설치해야 한다. 이번 수정에 따른 Worker 재배포는 필요 없다.
