## 4. 발견한 오류와 보완 결과

1. **서울 응답의 ETA 역순:** 실제 제공 JSON은 첫 슬롯 312초, 둘째 슬롯 219초였다. 기존 배열 우선 선택으로 늦는 버스가 첫 차량이 되고 219초 차량은 다음 차량으로도 연결되지 않았다. 이제 219초 차량을 먼저 선택하고 312초를 다음 차량으로 연결한다.
2. **선택 정보의 처리 불일치:** 수신 파서는 선택적 방향·유형 누락을 허용했으나 저장 복원과 백그라운드 요청은 거부했다. 동일 정책으로 맞췄다.
3. **통과 관측 유실:** 시간표 재시도에 빈 관측을 넣어 통과 열차 제외 근거가 사라질 수 있었다. 시간표 단독 모드에도 원래 관측을 전달한다.
4. **위치 추정 대체 경로의 불일치:** 두 위치명이 모순되거나 미래 시각이 명확해도 대체 경로가 한쪽 이름과 현재 시각을 사용할 수 있었다. 정상 위치는 계속 추정하고, 이 경우에는 위치 추정 대신 구분된 시간표 안내를 사용한다.
5. **보정 속도의 화면/서비스 차이:** 독립적인 평활화 결과와 설정 변경 시 보정값 누락 때문에 서로 다른 도보시간을 계산할 수 있었다. 서비스의 보정값을 공유한다.
6. **백그라운드 보정 표본 소실:** 30초 표본 보관에 30초 이상 걸리는 서비스 폴링이 겹치면 2개 표본이 쌓이지 않았다. 표본 구간을 90초로 늘리고, 속도값 자체의 현재 유효기간은 30초로 유지했다.
7. **서울 노선의 경기 재조회:** 서울 노선 확인 후 경유 순서 인증 실패를 서울 노선 없음으로 처리할 수 있었다. 제공기관 확인과 방향 확인 실패를 분리했다.

## 5. 실제 API 응답 검증

사용자가 제공한 운영 Worker JSON을 Android 실제 파서에 재생했다. 클라우드가 직접 성공 조회한 결과로 표현하지 않는다.

- `/bus/stops?query=06510`: `105900050`, `06510`, 경희대의료원.경희여중고와 좌표를 읽었다.
- `/bus/routes?stopId=105900050&arsId=06510`: 동대문01 `105900003`·승차순서 4와 동대문A01 `100000025`·승차순서 12를 별도 노선으로 읽었다.
- `/bus/arrivals?stopId=105900050&routeId=105900003&stopOrder=4`: 원본 생성 한국 시각 11:44:52, Worker 수신 11:44:59.085. 차량 `105000014`의 219초를 먼저 선택하고 `105000015`의 312초를 다음 차량으로 연결했다. 7.085초의 원본 경과 시간을 반영한 첫 ETA는 수신 시점 기준 211.915초다. 원본에 있던 `출발대기`·선택적 불확실 상태만으로 312초 ETA를 제외하지 않는다.
- `/bus/route-stops?routeId=105900003`: 제공된 실제 결과는 `BUS_UPSTREAM_KEY_REJECTED`다. 따라서 **동대문01의 실제 경유 순서와 회기역 방향 자동 확정은 아직 성공 검증하지 못했다.** ETA 수신 성공과 별도 결과다.
- 지하철: 이전에 수신·보관된 망포 응답과 공식 수인분당선 시간표의 재생 검증은 통과했다. 1호선은 포함된 공식 시간표에 관측을 구성한 검증이다. **이번 작업에서 최신 1호선·수인분당선 실시간 HTTP 성공 조회 또는 휴대폰 수신을 확인한 것은 아니다.**

클라우드의 직접 `/health`, 경유 순서, ETA 요청은 모두 HTTP 403 / Cloudflare 1010이었다. 이 결과는 서울 원본 API 자체의 장애를 증명하지 않는다.

## 7. 남은 사항과 운영 설정

1. **서울 노선정보조회서비스 인증:** ETA API가 성공하더라도 노선 경유 API는 별도 서비스 요청이다. 운영 Worker의 `SEOUL_BUS_KEY`가 `busRouteInfo/getStaionByRoute`를 호출할 수 있는지 공공데이터포털의 이용 서비스·승인 상태 및 인증키 적용 범위를 확인해야 한다. 제공된 오류만으로 승인 누락 또는 특정 키 값 문제를 단정하지 않는다. 임의로 키를 교체하지 않았다. Android에 버스 키를 넣을 필요가 없다.
2. 인증 정상화 후 실제 경유 응답에서 `105900050`의 순서 4 이후 첫 하차역 회기역이 있는지 확인해야 한다. 최종 목적지 수원역을 첫 버스 하차역으로 대체하지 않는다. 성공 전에는 방향을 임의로 확정하지 않으며, 사용자의 공식 정류소·노선 수동 선택은 유지한다.
3. 휴대폰에서 원거리 GPS/지정 출발지, 지도 두 경로·접기·확대 후 카메라 유지, 앱 백그라운드·화면 꺼짐 상태의 알림을 확인해야 한다. 카카오 지도 인증 권한, Android 알림·위치 권한과 기기 절전 조건은 실기기 확인 대상이다.
4. 현재 작업 브랜치의 변경을 유지하며 **main 병합 및 운영 Worker 배포는 수행하지 않는다.** 승인 후 별도로 진행한다. 이번 Android 수정 반영에는 APK 재빌드·재설치가 필요하다. Worker 코드는 바뀌지 않았으므로 이번 수정만으로는 Worker 재배포가 필수는 아니며, 노선정보 인증 정상화는 별도로 필요하다.
