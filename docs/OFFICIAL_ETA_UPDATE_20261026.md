# 공식 도착정보 우선 사용 수정 — 2026-10-26

공식 도착시간을 받았어도 차량 ID·부가 상태·초 단위 정밀도·원본 생성 60초 제한이
앞에서 걸러 주요 안내와 백그라운드 판단이 멈추던 문제를 수정했다.

## 동작 변경

- 경기 GBIS의 4분/8분은 차량 ID·응답 순번·정류소 순서 부가 필드가 없어도 즉시 사용한다.
  분 단위 API는 분 단위로 표시한다. 실제 정류소·노선과 이미 확인한 승차 방향은 유지한다.
- 서울 버스·지하철도 양수 공식 ETA를 우선 사용한다. 선택 필드 누락만으로 제외하지 않는다.
  원본 생성 후 60초 초과만으로 버리지 않고 경과 시간을 빼서 남은 시간을 계산한다.
- 원본 정보의 최대 나이는 10분, 성공 응답 수신 후 재사용은 최대 60초다. 공식 ETA가
  이미 지났거나 음수·비정상 값, 운행 종료, 실제 노선·정류소 불일치는 제외한다.
  작은 시계 차이는 60초까지 허용한다. 원본 시각이 없으면 수신 시각을 계산 기준으로
  사용하며 원본 시각을 만들지 않는다.
- 화면의 ETA 표시는 GPS·도보 경로 성공과 분리한다. 걷기/빠른 걸음/다음 차량 판단에는
  현재 위치와 실제 승차 지점까지의 도보 시간이 여전히 필요하다. 전면 화면과 화면을
  끈 뒤 서비스가 같은 ETA 선택 함수를 사용한다.
- 정류장 찾기에서 목적지를 선택해 첫 지하철 구간의 하차역을 연결하고, 공식 정차 순서로
  해당 방향의 열차를 선택한다. 경로 찾기도 같은 공식 도착정보와 시간표 분석을 사용한다.
  길찾기의 두 번째 표시 역을 실제 인접역으로 가정해 수신 행을 지우던 조건을 완화했다.
- 양수 지하철 ETA가 없으면 동봉한 공식 시간표와 현재 열차 위치를 대조한다.
  원본 관측 5분 이내이고 열차·정차 경로·요일이 확인된 경우에만 시간 범위를 추정한다.
  화면과 알림에 ‘시간표 추정’을 표시한다. 데이터 출처·제외 범위·재생성 절차는
  [시간표 README](../app/src/main/assets/timetables/README.md)를 따른다.
- M으로 시작하는 이름만으로 서울 공급자로 단정하지 않는다. GBIS의 실제 정류소와
  노선 목록으로 연결하고, 선택적인 종착지 표기 차이가 유일한 공식 연결을 무효화하지 않는다.

주요 변경은 `SeoulSubwayRepository`, `SeoulBusModels/Repository`,
`GyeonggiBusRepository/ArrivalMatching/Lookup`, `AutoGuidance`, `SubwayTimetableAnalysis`,
`MainActivity`, `OfficialArrivalStatusCard`, `JourneyMonitoringService` 및 Worker의
`model.ts`, `bus-model.ts`, `gyeonggi-bus-model.ts`에 있다.

## 확인 및 운영상 남은 사항

Android Kotlin 컴파일·debug APK 조립과 Worker TypeScript 검사·배포 dry-run을 확인했다.
저장소에서 삭제한 테스트 소스나 테스트 의존성은 복원하지 않았다. 별도 작업 디렉터리의
재현 19건이 통과했다. 분 ETA/차량 ID 누락/시간 경과 처리와 공식 망포 응답의
방향·시간표 연결을 확인했다. Worker 별도 재현도 GBIS 4분/8분, 선택 필드 누락,
원본 90초 지연, 캐시 만료, 운행 종료·음수 ETA·이미 출발한 열차 처리를 확인했다.

현재 환경의 실제 M5107 조회는 공식 데이터에 도달하기 전 Cloudflare HTTP 403,
오류 1010으로 막혔다. 운영 정류소 ID나 실제 4분/8분 수신 성공을 확인했다는 뜻은 아니다.
기존 서울 버스 인증 거부(`BUS_UPSTREAM_KEY_REJECTED`)는 코드 수정으로 인증키 권한이
생기지 않으므로 운영 `SEOUL_BUS_KEY`와 승인 서비스 확인이 별도로 필요하다.

2026-10-26 운영 배포를 시도했으나 이 환경에 Cloudflare 인증이 없어 Wrangler가
`CLOUDFLARE_API_TOKEN` 필요 오류로 중단했다. 운영 서버는 새 버전으로 변경되지 않았다.
인증된 PC에서 병합한 버전을 받은 뒤 다음 명령으로 배포할 수 있다.

```powershell
git pull origin main
cd worker
npm ci
npx.cmd wrangler login
npm run deploy
```

API 키는 기존 Worker secrets를 유지하며 저장소·APK에 넣지 않는다. 새 공식 시간표에는
추가 API 키가 필요하지 않다. 실기기 지도·권한·화면 종료 알림 동작은 별도 실기기 확인이 필요하다.
