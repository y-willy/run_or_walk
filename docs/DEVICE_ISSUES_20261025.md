# 실기기 오류 4건 진단과 수정 — 2026-10-25

이 문서는 버스 추가 전 오류 수정 기록이다. 이후 [서울 버스 연동](SEOUL_BUS_INTEGRATION.md)을 추가했으며 현재 위치 요청은 10초 이내 캐시를 우선해 20초 자동 갱신 사이에 30초 유효기간이 만료되는 공백을 줄였다. 자동 판단의 위치 유효기간 상한 30초는 유지한다. Kakao 콘솔 등록 확인은 사용자가 완료했다고 알려왔다.

앱 코드 수정과 APK 빌드를 완료했다. 지도 서버 인증과 배포된 Worker의 응답은 외부 계정 설정이므로, 소스 변경만으로 정상화됐다고 판단하지 않는다. 이 환경에 카카오 콘솔·Cloudflare 배포 인증은 없다.

## 실제 서비스와 시간 확인

2026-10-25 **16:06 KST**에 앱과 동일한 `PaceNudge/1.0 (Android)` 식별자로 기존 `/health`와 강남 `/subway`를 각각 확인했고 모두 HTTP 200이었다. 최소 확인 조회이며 반복 부하 테스트는 하지 않았다.

강남 응답 7행에서 원본 열차 번호 `btrainNo`와 도착 상태 `arvlCd`가 모두 누락됐고, 3행은 ETA 0초였다. `fetchedAt=2026-10-25T07:06:38.443Z` 기준 2호선 원본은 약 26초 전이지만 신분당선 원본은 약 240~264초 미래였다. 따라서 전체 네트워크 장애나 모든 데이터의 지연으로 설명할 수 없다. 앱은 받은 원본 메시지를 표시하되 이 데이터로 확정 탑승 판단을 하지 않는다.

UTC `fetchedAt`과 한국 시각 `receivedAt/recptnDt`는 각각 올바른 시간대로 해석한다. 새로 받은 시각을 원본 생성 시각으로 대체하지 않는다. 미래 시각·0초·실제 차량 식별정보 누락을 유효한 ETA로 바꾸거나 임의 열차 번호를 생성하지 않는다.

## 위치·도보·도착정보의 독립 갱신

화면이 보이는 동안 승차 장소가 있으면 위치·도보 상태를 약 20초마다 확인한다. 실제 도보 경로가 90초 이내이며 이동 거리가 25m 이내면 재사용하고, 방향 변경 시 검증된 같은 도보 응답에만 새 공식 방향을 연결한다. 도착정보는 기존 정책대로 약 30초마다 조회하며 `Retry-After`를 우선한다. 수동 위치 재조회·역 변경·탭 변경 이후 오래된 자동 요청은 결과를 덮어쓰지 못한다.

이후 사용자 요청에 따라 초기 24시간 대기를 제거했다. 새 Worker를 배포하면 저장된 초기 대기만 해제하며 실제 호출 장부·900회 상한은 유지한다. 이전 Worker의 BUDGET_WARMUP을 받은 앱도 30초 이내에 재확인하며 실제 사용량 제한의 대기 시간은 단축하지 않는다. 기존 `SEOUL_SUBWAY_KEY`는 Cloudflare Secret 그대로 사용하며 다시 입력하거나 앱에 넣지 않는다.

## 검증과 설치 후 확인

앱의 `:app:compileDebugKotlin`, `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:lintDebug`를 통과했다. 단위 테스트 **109개**, 실패·오류·건너뜀 0개다. 린트 오류는 0개이며 경고 30개·힌트 1개가 남아 있다. 이 수정에서는 Worker 소스와 의존성을 바꾸지 않았고, 이전의 Worker 133개 테스트 기록과 구분한다.

새 회귀 테스트는 최근 위치·정확도·미래 관측 시각, API 오류 분류, 실제 서명 해시 형식, 기존 강남 Worker 응답, 원본과 기기 시계의 불일치, 유일한 역·호선 자동 연결 및 모호한 후보 거절을 검증한다.

1. 새 APK를 설치하고 위치 권한의 **정확한 위치** 및 기기 위치 서비스를 켠다. 위치 획득과 경로 조회의 개별 안내를 확인한다.
2. 지도 오류의 **지도 인증 설정**에서 실제 설치 APK 정보를 복사해 Kakao 콘솔에 등록한 뒤 지도를 재시도한다. PC와 클라우드의 디버그 서명은 다를 수 있다.
3. 경로를 선택해 승차역·호선의 자동 연결을 확인한다. 모호한 환승역·방향만 선택하고 다른 역·탭으로 바꾸는 중 늦은 응답이 섞이지 않는지 확인한다.
4. 새 Worker를 기존 계정·기존 이름에 배포한 후 원본 필드·신뢰도·캐시를 소량 조회로 확인한다. 미래·0초·오래된 원본은 확정 안내하지 않아야 한다.

실제 스마트폰의 지도 표시·GPS 수신·운행 정확도 검증과 외부 콘솔 설정은 아직 완료되지 않았다.
