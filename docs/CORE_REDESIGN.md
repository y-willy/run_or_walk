# 서울 지하철 중심 핵심 기능 재설계 보고

> 이전 단계의 기록입니다. 현재 Cloudflare 주소·응답·판단 상태·배포 절차는 [Worker 연동 보고](WORKER_INTEGRATION.md)를 확인하세요.

## 1. 기존 문제별 원인

지도 SDK 2.15.2 바이트코드에서 `setFinishManually(true)`를 `start()` 전에 호출하면 적용되지 않는 것을 확인했다. 기존 코드는 이 순서를 위반했다. 초기화 실패는 앱 전체를 종료했고, 지도 콜백이 없을 때의 시간 초과도 없었다. 실제 기기 인증 실패 원인은 앱 서명 등록과 로그를 추가 확인해야 한다.

기존 화면은 네 가지 제공자/탭 조합과 중복 카드가 복잡도를 높였다. 수동 입력 도착시간만으로 계산했고 실제 차량·방향, GPS 정확도와 데이터 생성 시각을 사용하지 않았다.

## 2. 수정한 파일

- `MainActivity.kt`, `JourneyScreenState.kt`, `PaceNudgeComponents.kt`: 두 탭·검색·핵심 결과·지도, GPS 출발, 독립 상태, 정확한 역·호선·차량 선택.
- `KakaoApiRepository.kt`, `TransitModels.kt`: Kakao 검색 통합과 최대 세 경로, 실제 도보·환승 메타데이터만 사용. `TransitRepository.kt`의 ODsay 요청 구현 제거.
- `LocationHelper.kt`: 위치 측정 정확도와 실제 생성 시각 유지.
- `AutoGuidance.kt`: WALK/RUN/NEXT/UNKNOWN, 신선도·식별·GPS 검사, 탭 간 중복 진동 방지.
- `SeoulSubwayRepository.kt`, 공식 역 asset: 공식 ID 기반 목록·응답 파싱, 앱의 HTTPS 중계 연결. 공식 인증키를 APK에서 제외.
- `PaceNudgeApplication.kt`, `kakaomapkanel.kt`, `MapLoadFailure.kt`: 지도 호출 순서·초기화·수명주기·시간 초과·오류 코드·재시도.
- `app/build.gradle.kts`: ODsay 키 필드 제거, 중계 설정만 사용, JSON 파서 테스트 의존성.
- `gateway/`: Python 서버·테스트, Caddy HTTPS, Docker/Compose 배포 설정. `.dockerignore`는 키·로컬 설정·빌드 결과를 빌드 컨텍스트에서 제외.

## 3. 지도 로딩 오류 해결 범위

확인된 호출 순서를 수정하고, 초기화 실패가 앱 전체를 종료하지 않게 했다. 기억된 MapView, 실제 좌표 마커·도보선, 확대/축소와 현재 위치 버튼을 유지한다. 콜백은 종료 여부를 확인하고, foreground 로딩이 20초를 넘으면 오류와 재시도를 표시한다. 원문 SDK 오류·키·좌표를 출력하지 않고 `PaceNudgeMap` 태그의 분류·숫자 코드만 기록한다.

**기기에서 지도가 실제 표시됐다고 검증하지 못했다.** 카카오 Android 설정의 `com.example.run_or_walk`와 실제 설치 APK의 서명 키 해시가 일치해야 한다. PC별 디버그 키·릴리스/Play 서명은 다를 수 있다. 기기 확인 명령은 `adb logcat -s PaceNudgeMap`이며 원문 네트워크 로그·키는 공유하지 않는다.

## 4. 삭제·통합한 UI

탭은 `경로로 찾기`와 `정류장 찾기`만 표시한다. 제공자 선택·수동 도착시간 중심 UI·중복 승차/도보 카드를 제거했다. 핵심 결과를 경로 목록보다 앞에 배치한다. 경로는 최대 세 개이고 선택 항목만 상세를 보인다. 승차 변경·공식 역/열차 선택은 하나의 접이식 영역으로 통합했다. 지도는 한 인스턴스의 높이만 확장한다. 공식 ID 숫자를 사용자용 설명으로 노출하지 않는다.

## 5. Kakao 단일 경로 제공자

장소/정류장 검색·대중교통·실제 도보 경로는 기존 Kakao 호출을 유지한다. ODsay 요청과 빌드 키는 제거했다. API가 주지 않은 도보시간·환승 횟수·공식 ID는 생성하지 않는다. 실시간 식별이 연결되지 않은 경로의 소요시간 순위는 **추정**이며 차량 탑승 가능성을 검증한 순위가 아니다.

## 6. 실시간 API 지원 범위

사용자 선택에 따라 서울 지하철을 우선하고 **HTTPS 중계 방식의 배포 코드**를 준비했다. 실제 서버·도메인이 아직 없고 서울 실시간 지하철 전용 키도 없어 공개 배포하지 않았다. 제공기관·필드·일 1,000건 한도·발급·지역 제한·라이선스는 [공식 API 조사](REALTIME_API_RESEARCH.md)에, 배포 절차는 [중계 서버 안내](../gateway/README.md)에 있다.

공식 목록 696개에는 일부 경기권 역이 있지만 역·호선·방향별 실제 제공 여부는 미검증이다. 이 API에는 버스 도착정보가 없다. 버스 경로 검색은 유지하며 실시간 판단은 확인 필요로 남긴다. 지역별 버스 API와 추가 권한 없이 도착시각을 만들지 않는다.

## 7. 자동 판단 구현 범위

공식 역 ID·호선 ID·방향·종착/운행 종류와 선택 열차를 일치시킨다. 이름만으로 첫 후보를 자동 연결하지 않는다. 공식 목록에 좌표가 없어 지도 승차 장소와의 연결은 사용자의 명시적 선택이 필요하다.

- WALK: 실제 도보시간 + 안전 여유 ≤ 차량 도착까지 시간.
- RUN: 일반 도보로는 부족하지만 `ceil(도보 초 × 0.75)` + 안전 여유는 확보됨. 빠른 이동은 **추정**이며 신호·보행환경·개인 속도를 측정한 값이 아니다.
- NEXT: 추정 빠른 이동으로도 부족함. 다음 시각은 같은 역·호선·방향·운행 종류의 실제 다른 열차가 있을 때만 표시한다.
- UNKNOWN: 권한·GPS·승차 식별·실시간 응답·신선도 중 조건이 부족함. 수동값이나 샘플로 확정 판단하지 않는다.

안전 여유 기본 120초, GPS 정확도 50m 이하/생성 후 30초 이내, 도보 최대 120초·출발점 차이 35m 이내, 도착정보 최대 30초를 앱 정책으로 사용한다. 제공기관의 보장치가 아니다. `recptnDt`는 오프셋이 없어 한국 시각으로 해석하는 가정을 기록했다. 다음 열차를 포함하면 두 정보 중 먼저 만료되는 시각을 적용한다.

자동 진동은 기본 꺼짐이다. 켜도 같은 열차·상태의 갱신, 탭 전환, UNKNOWN 후 회복은 반복 진동하지 않는다. 탭 간 공유 제한과 30초 cooldown을 사용한다. 기존 진동 파형과 수동 계산 함수는 유지했다.

## 8. 빌드·테스트 결과

원래 프로젝트에서 `:app:compileDebugKotlin`, `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug`가 모두 성공했다. 앱 단위 테스트 **66개 통과**, 실패·오류·건너뜀 없음이다. 린트는 **오류 0개·경고 25개·힌트 1개**다.

중계 서버 단위/HTTP 통합 테스트 **9개 통과**. Docker 이미지 빌드와 일반 사용자 권한 실행, 설정 누락 시 HTTP 503을 반환하는 실제 컨테이너 동작, Compose 설정과 Caddy HTTPS 설정의 유효성을 확인했다. 처음 컨테이너 실행에서 발견한 파일/상위 디렉터리 권한 문제는 수정 후 재검증했다.

공개 샘플은 테스트 전용이다. 공개 HTTPS 인증서 발급·실제 서버 배포·전용 키 인증·실운행·기기 계측 테스트는 실행하지 않았다. 지도 단위 테스트 4개는 오류 분류를 확인하며 실제 MapView 수명주기 검증을 대체하지 않는다.

## 9. 실기기 미검증 항목

지도 인증·렌더링, 회전/복귀/재시도·제스처·도보선, 실제 GPS·권한 거부·이동 재계산, 서울 공식 열차와 경로 매칭, 실제 진동, 작은 화면·큰 글꼴·키보드·TalkBack. 지도 오류 분류 단위 테스트는 MapView 기기 수명주기 테스트가 아니다.

## 10. 다음 작업과 제약

서버·도메인과 전용 키를 준비해 중계를 배포하고 실제 응답을 확인한 뒤, 앱의 로컬 중계 주소/접근 토큰을 설정해 다시 빌드해야 한다. 아직 앱은 실시간 연결 필요(UNKNOWN)를 표시한다. 현재 APK만 설치하면 실시간 자동 판단이 완성되는 상태라고 주장하지 않는다. 전체 후보 경로의 자동 차량 매핑·탑승 가능성 일괄 추천과 경기권 전체 지원도 검증되지 않았다.
