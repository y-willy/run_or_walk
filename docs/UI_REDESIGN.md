# PaceNudge UI/UX 리디자인

## 화면 구조와 변경점

기존 화면은 지도, 카카오 장소 검색, 정류장 검색, 두 경로 검색 제공자와 긴급도 입력이 하나의 긴 폼에 섞여 있었다. 이제 `기능 1 · 경로로 찾기`와 `기능 2 · 정류장 찾기`를 상단 탭으로 나누고, 각 기능 안에서 검색 → 선택 → 승차 지점 → 지도·도보 요약 → 긴급도 순서로 안내한다.

Navy `#0F172A`, Mint `#14B8A6`, 밝은 배경 `#F6F8FC`를 기준으로 Material 3 색상·타이포그래피·모서리를 통일했다. 다크 테마도 제공하며, 시스템 동적 색상은 명시적으로 선택할 때만 사용한다. 상태는 색뿐 아니라 배지·문구·기호로 전달한다. 차량 도착시간에는 항상 **수동 입력**임을 표시하며 실시간 도착정보를 생성하지 않는다.

## 상태와 기능 보존

| 상태 | 관리 범위 | 변경 시 처리 |
| --- | --- | --- |
| 출발지·도착지·정류장 검색어, 후보, 선택 | 기능 × 검색 제공자별 | 검색어 변경 시 해당 선택과 후속 경로 무효화 |
| 대중교통 경로, 승차 위치, 위치 신뢰도, 승차 후보 | 기능 × 검색 제공자별 | 새 출발·도착·승차 선택에 맞춰 갱신 |
| 도보 경로·좌표·지도 중심·긴급도 | 기능 × 검색 제공자별 | 승차 위치 변경 시 도보·긴급도 초기화, 시간 입력 변경 시 긴급도만 초기화 |
| 도착시간·안전 여유시간·스크롤 | 기능 × 검색 제공자별 | 탭과 제공자 전환 시 보관 |
| GPS 좌표 | 센서 결과 공유 | 실제 위치 요청 성공 시에만 표시 |
| 비동기 작업·권한 요청 | 요청 당시 화면·버전 | 오래된 응답이 현재 선택을 덮어쓰지 않도록 확인 |

카카오 장소 검색, 카카오·ODsay 대중교통 검색, FusedLocationProvider 위치 조회, Kakao 지도와 실제 도보 좌표, 승차 후보 직접 선택을 유지한다. `KakaoApiRepository.kt`, `TransitRepository.kt`, `LocationHelper.kt`, `PaceNudgeApplication.kt`의 기존 API 구현과 SDK 초기화는 변경하지 않는다. 추가 실시간 API나 AI 모델, 새 아키텍처 라이브러리는 도입하지 않는다.

경로에서 추정하거나 확인하지 못한 승차 위치에는 경고를 표시한다. 후보 첫 항목을 자동 선택하지 않는다. 사용자가 선택한 장소도 실제 정류장·출입구와 일치하는지 확인하도록 안내한다. ODsay 모델에 없는 환승 횟수나 주소를 만들어 표시하지 않는다.

## 주요 파일과 컴포넌트

- `MainActivity.kt`: 두 기능과 제공자 선택, 검색·GPS·권한·도보 요청, 수동 시간 입력, 결과 연결.
- `JourneyScreenState.kt`: 네 가지 기능/제공자 조합의 상태, 선택 변경에 따른 무효화, 요청 버전 관리.
- `PaceNudgeComponents.kt`: 헤더, 기능 선택, 검색·경로·승차·도보·긴급도 카드, 빈 상태·로딩·오류 안내. 작은 화면과 다크 테마용 Preview 포함.
- `kakaomapkanel.kt`: 유지되는 `MapView`, 민트 도보선, 실제 좌표 마커, 현재 위치·확대/축소, 지도 로딩·오류·재시도, 수명주기와 터치 처리.
- `ui/theme/Color.kt`, `Theme.kt`, `Type.kt`: 공통 디자인 시스템.
- `UrgencyCalculator.kt`: 두 기능이 공유하는 기존 긴급도 계산과 입력 스냅샷.
- `res/values/strings.xml`: 앱 표시 이름 `PaceNudge`.
- `UrgencyCalculatorTest.kt`, `JourneyScreenStateTest.kt`: 경계값과 상태 격리 회귀 검증.

## 긴급도와 진동

기존 식 `여유시간 = 차량 도착(분) - 도보(초)/60.0 - 안전 여유(분)`을 그대로 사용한다.

| 여유시간 | 단계 | 진동 횟수 |
| --- | --- | --- |
| 3분 이상 | NONE | 0 |
| 1분 이상 ~ 3분 미만 | LOW | 1 |
| 0분 이상 ~ 1분 미만 | MEDIUM | 2 |
| -2분 이상 ~ 0분 미만 | HIGH | 3 |
| -2분 미만 | MISSED | 0 |

진동은 사용자가 계산 버튼을 눌렀을 때만 실행하며 기존 진동 파형을 유지한다. 지원하지 않는 기기는 화면으로 안내한다. 음수·무한대·NaN 입력은 허용하지 않는다.

## 검증과 현재 제한

원래 프로젝트의 실제 Android·Kakao SDK 의존성으로 검증했다. 컴파일 성공을 실제 기기 동작 검증으로 간주하지 않는다.

- JDK 25, Gradle 9.6.0, Android SDK 37.0, Build Tools 36/37 설치와 설치 스크립트 재실행 확인.
- 저장소 `gradlew projects` 성공.
- `:app:compileDebugKotlin`, `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug` 성공. 디버그 APK 생성 확인.
- 실제 앱 단위 테스트 **20개 통과**: 기존 테스트 1개, 긴급도 경계값·입력 검증 13개, 상태 격리·무효화·위치 경고 6개. 실패·오류·건너뜀 없음.
- 린트 **오류 0개·경고 22개·힌트 1개**. 의존성 업데이트 제안·기존 미사용 리소스·스타일 및 접근성 관련 제안이 남아 있으며 테스트·의존성 버전을 임의로 바꾸거나 검사를 끄지 않음.
- 초기에 차단되었던 `devrepo.kakao.com`의 Kakao SDK 다운로드는 이후 성공했으며 실제 SDK 2.15.2로 컴파일함.
- 제공된 키를 Git에서 제외된 `local.properties`에 반영해 재빌드했으며, 세 키가 APK에 반영된 것을 값 노출 없이 확인함. 서명 검증과 단위 테스트 20개도 다시 통과함.
- 실제 Kakao 장소 검색은 후보 3개, ODsay 정류장 검색은 후보 3개를 반환함. 기존 Kakao 도보·대중교통 경로 API도 HTTP 200 및 `OK` 상태를 반환했으며, 대중교통 경로는 15개를 반환함. 실제 기기의 Repository 파싱과 화면 표시까지 검증했다는 뜻은 아님.
- 지도 렌더링·제스처, ODsay 경로 검색, 기기 GPS·진동·TalkBack·키보드·화면 배치는 아직 직접 검증하지 못함. 에뮬레이터·계측 테스트도 실행하지 않음.

키를 반영한 APK 위치는 `app/build/outputs/apk/debug/app-debug.apk`이다. 키 값은 소스·보고서·설치 스크립트·환경 초안에 기록하지 않았다. 카카오 Android 설정에는 패키지 `com.example.run_or_walk`와 이 APK의 서명 키 해시를 등록해야 한다. 공개 서명 정보는 같은 출력 디렉터리의 `kakao-android-registration.txt`에 있다. 앱 전체의 시작과 기기에서의 검색 성공까지 확인했다는 뜻은 아니다.

Linux 검증 명령:

```bash
source /workspace/.cloud-setup/activate.sh
cd /workspace/run_or_walk
bash gradlew :app:compileDebugKotlin :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --no-daemon --max-workers=4 --console=plain
```

Windows Android Studio 터미널에서는 프로젝트 루트에서 `gradlew.bat :app:compileDebugKotlin`을 실행한다. 빌드 의존성은 선언된 버전을 유지한다.

## 스마트폰 확인 항목과 다음 작업

1. 안전하게 준비한 `local.properties` 키로 실행한다. 빈 Kakao native 키는 기존 Application 초기화에서 실행을 중단한다. 키를 채팅·로그·커밋에 남기지 않는다.
2. 두 탭과 Kakao/ODsay 전환 후 검색어·선택·도보·시간 입력이 보존되고 다른 화면의 결과가 섞이지 않는지 확인한다.
3. 출발·도착 후보, 정류장 후보, 경로와 승차 후보를 직접 선택하고 실제 API 결과와 일치하는지 확인한다.
4. 위치 권한 허용·거부·대략적 위치, GPS 꺼짐, 네트워크 실패·빈 검색·도보 경로 없음 안내를 확인한다.
5. 지도 현재 위치와 승차 마커, 실제 도보선, 현재 위치 버튼·확대·축소·재시도와 지도/스크롤 제스처를 확인한다.
6. 수동 도착시간과 여유시간을 바꾸고 모든 긴급도 단계 및 0/1/2/3/0회 진동을 확인한다. 재구성이나 탭 전환만으로 진동하면 안 된다.
7. 작은 화면, 큰 시스템 글꼴, 다크 모드, 키보드 표시, 화면 회전, 앱 백그라운드 복귀와 TalkBack으로 잘림·접근성·지도 수명주기를 확인한다.

다음 작업은 실제 키와 기기를 사용한 위 시나리오 확인이다. Kakao 경로 API의 HTTP 응답과 상태는 확인했으며, 기기에서의 Repository 파싱과 화면 연결 및 ODsay 경로 검색은 별도 확인이 필요하다. 이번 UI 작업에서 API 연동 범위를 확장하지 않는다.

## 클라우드 환경 재사용

설치 및 활성화 보조 파일은 체크아웃 밖 `/workspace/.cloud-setup`에 보관한다. `install_script`, `start_skill`과 필요한 저장소 도메인 설정은 환경 초안에 저장한다. 게시와 새로운 작업에서의 복원은 별개이며, 이번 작업에서 게시·새 작업 복원을 실행했다고 주장하지 않는다. 환경 설정에서 저장된 내용을 검토·저장한 뒤 게시한다.
