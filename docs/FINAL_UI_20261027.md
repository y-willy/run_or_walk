UI 문구는 기존 WALK / FAST_WALK / NEXT_VEHICLE / UNKNOWN을 각각 `걸으세요` / `빠르게 이동하세요` / `다음 차량 이용` / `정보 확인 중`으로 표현한다. 상태 산출, 달리기 속도 조건, 진동/백그라운드 정책은 변경하지 않았다.

이동 여유 = `(차량 도착 절대시각 - 현재 시각) / 1000 - 기존 도보시간 - 기존 승차 준비 여유시간`.
이미 계산된 절대 ETA를 표시하며 중복 시간 차감을 하지 않는다. 상위 코드에서 유효하다고 판정한 실시간 또는 시간표 ETA만 이용하며, 최신 기존 계산기가 ETA와 도보시간을 모두 산출한 경우에만 여유시간을 표시한다. 유효하지 않은 ETA에는 여유시간을 생성하지 않는다. 기존 진행 막대는 제거했고, 상세 도착시각은 여유시간 행을 눌러 확인한다.

## 시안 대비 구현 및 이미지

라이트/다크의 배경, 청록 안내 카드, 발자국 마크, 둥근 카드, 지도 우선 배치, 하단 아이콘, 즐겨찾기 구조를 반영했다. 시안의 예시 노선/시간/위험도 등은 앱 데이터에 하드코딩하지 않았다.

아래 이미지는 **실제 수정한 Compose 컴포넌트 + 모의 데이터의 Robolectric native graphics 렌더**다. 실기기 캡처 또는 운영 API 실측이 아니다. 메인은 동일한 운영 컴포넌트를 구성한 UI 검증용 화면이고, 즐겨찾기는 실제 `FavoriteBusesScreen`을 렌더했다. 상태바/시스템 내비게이션은 테스트 창 특성상 시안과 다르다.

Kakao Map의 네이티브 타일 엔진은 이 테스트 환경에서 구동하지 않는다. 따라서 제출 이미지에는 지도 영역에 **테스트 환경임을 알리는 빈 패널**을 표시했다. 지도 시안이나 임의 도로 이미지를 실제 결과처럼 사용하지 않았다. 이 패널은 테스트 소스에만 있으며 APK에는 들어가지 않는다. 실제 앱에는 기존 `KakaoMapPanel`/Kakao SDK가 그대로 연결되어 있다.

## 기존 기능 보존과 검증 범위

- 서울/경기 공식 ID 저장·방향 검증·ETA 파서·선택 어댑터·캐시/호출 제한 구현은 수정하지 않았다. 즐겨찾기 선택 버튼은 검증된 공식 승차정보를 기존 복원 함수에 전달한다.
- 지하철 실시간/위치+시간표 ETA 계산기, GPS 속도 보정, 이동 판단, 백그라운드 서비스/진동, Worker 소스는 변경하지 않았다.
- 화면과 백그라운드의 판단 결과는 기존 공용 계산기를 그대로 사용한다.
- 실제 경로 좌표를 그리는 Kakao Map 호출과 핸들러를 그대로 이동했다. 현위치와 지정 출발지가 15m 이내인 경우 중복 접근 경로를 만들지 않는 기존 처리도 유지한다. GPS/출발지 변경에 따른 지도 갱신, ETA만 바뀔 때 지도 재요청을 하지 않는 기존 구조도 유지했다.
- UI 테스트는 모의 공식 응답을 주입한다. 기존 실제 수신 JSON을 사용한 파서 회귀 테스트는 과거 응답 재생이며, 현재 운영 API의 새 실측이 아니다.

## 실기기 추가 검증

1. 실제 Kakao Map 인증·타일 로딩, 파란 접근 경로/초록 본 경로, 마커·줌·현위치·지도 조작 후 카메라 유지.
2. 짧은 화면에서 검색/승차 선택을 마친 실제 활동 화면의 지도 노출 높이, 긴 정류장/행선지 이름, TalkBack 및 큰 글꼴.
3. 실제 서울·경기 버스/지하철 운영 API 수신 및 즐겨찾기 선택 후 GPS/도보시간 연결.
4. 즐겨찾기 별칭 편집창의 실제 키보드 입력·저장·취소. 네이티브 편집창은 Robolectric의 팝업/입력 동기화가 끝나지 않아 자동 UI 검증 완료로 처리하지 않았다. 별칭 로컬 저장 자체는 별도 회귀 테스트로 검증한다.
5. 실제 GPS 이동, 화면을 끈 상태의 Foreground Service·알림·차등 진동, OS 권한 거부/회수.

이 작업에서 새 API 키·Worker 설정·서버 배포는 필요하지 않다. 기존 앱 지도 및 게이트웨이 설정을 사용한다. main 병합과 운영 Worker 배포는 수행하지 않았다.
