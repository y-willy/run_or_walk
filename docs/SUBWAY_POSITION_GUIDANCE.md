# 지하철 원본 위치·운행 메시지를 주 안내에 반영

## 변경

`barvlDt=0`이거나 열차 종류 같은 메타데이터가 없어도, 공식 API의 `arvlMsg2` 위치·운행 메시지를 **지금 이동 안내**에 사용한다. 기존에는 아래 원본 카드에 메시지가 있어도 위쪽 주 안내가 숫자 ETA를 기다리는 문구만 표시했다.

- 정류장 찾기에서는 선택한 공식 역·호선의 상행/하행 메시지를 행선지와 함께 안내한다.
- 추천경로가 있으면 그 경로의 다음 역·방향과 일치하는 메시지만 안내한다. 공식 운행 선택이 확정되어 있으면 해당 식별정보도 일치해야 한다.
- 신선한 원본은 `열차 위치 안내 중`, 60초 지난 원본은 `마지막 수신 열차 위치`로 표시한다. 원본 생성 후 경과 시간을 그대로 보인다. 오래된 메시지를 버리고 계속 확인 중으로 표시하는 대신, 언제의 정보인지를 밝혀 활용한다.
- 초 ETA 0을 `지금 도착`으로 해석하지 않는다. `[3]번째 전역`을 임의의 분·초나 탑승 가능 판단으로 환산하지 않는다. 숫자 ETA가 있는 경우 기존 도보시간 비교가 우선한다.
- 주 카드의 해당 칸을 `열차 위치·운행`으로 표시한다. 원본 카드에서도 0초 메시지를 `자동 판단 제외` 대신 `열차 위치 정보로 안내 중`으로 설명한다.
- 이미 실행 중인 화면 꺼짐 서비스도 원본 위치 메시지를 화면과 알림에 전달한다. 새로운 숫자 ETA·도착 임박 진동을 생성하지 않는다. 이 변경이 방향 미확정 상태에서 화면 꺼짐 서비스를 자동 시작하는 것은 아니다.
- 요청 실패, 미래 시각, 누락된 생성 시각, 다른 역·호선·방향은 성공한 위치 안내로 대체하지 않는다. 경로 변경 시 기존 세대 번호·선택 무효화가 유지된다.

핵심 파일: `SubwayOperationGuidance.kt`, `MainActivity.kt`, `PaceNudgeComponents.kt`, `JourneyMonitoringController.kt`, `JourneyMonitoringService.kt`, `SeoulSubwayRepository.kt`.

## 서울 버스 401

사용자가 전달한 `BUS_UPSTREAM_KEY_REJECTED`는 새 Worker가 서울 버스 원본에서 HTTP 401을 받았다는 뜻이다. Worker가 `SEOUL_BUS_KEY`를 전혀 찾지 못한 경우의 `SEOUL_BUS_NOT_CONFIGURED`와 다르다. 현재 정보만으로 등록 값 오류·제공자 인증 정책 중 정확한 사유를 확정할 수는 없다.

먼저 공공데이터포털의 승인된 **서울 버스정류소정보 조회 / 버스도착정보 조회**에 사용하는 인증키가 Cloudflare `SEOUL_BUS_KEY`에 등록되어 있는지 확인한다. Kakao 키와 서울 열린데이터광장 지하철 키는 다른 키다. Decoding 인증키의 값만 넣고 `serviceKey=` 접두사·따옴표를 넣지 않는다. Worker는 Decoding/Encoding 형태를 한 번만 URL 인코딩하도록 구현되어 있다.

로그인된 PC의 `worker` 폴더에서 안전한 대화형 입력으로 갱신할 수 있다:

```powershell
npx.cmd wrangler secret put SEOUL_BUS_KEY
```

키는 채팅·소스·로그에 보내지 않는다. 변경 후 `/bus/stops?query=강남역`을 다시 확인한다. 정확한 키로도 401이 지속되면 동일 승인 서비스의 제공자 테스트 호출 결과와 Worker 결과를 비교해야 한다. 승인 재신청이나 키 재발급이 반드시 필요한 상황이라고 단정하지 않는다. 이 환경은 해당 Secret을 읽거나 갱신하지 않았다.

## 적용

이번 수정은 **Android 앱 변경**이다. 수정 브랜치의 새 APK를 다시 빌드·설치해야 한다. 위치 안내 변경을 위해 Worker를 다시 배포할 필요는 없다. 서울 버스 Secret 확인·갱신은 별도 작업이다.
