## 1. 수정 전 구조 및 확인된 원인

사용자 설정 달리기 속도·개인 걷기 분석·GPS 정확도 및 평활화는 유지한다. 달리기 속도가 없다는 이유로 새 구간 판정을 막지 않으며, 임의의 달리기 시간을 사용자 측정값처럼 표시하지 않는다. `뛰세요`는 요청한 여유시간 구간 안내이며 실제 달리기로 탑승 가능하다는 보장은 아니다.

공식 실시간 ETA 우선, 없으면 기존 공식 위치·시간표 또는 시간표 예정 선택기를 그대로 사용한다. 추정은 출처 표시로 구분하며 분 정밀도는 유지한다. 다음 차량은 실제 유효한 후속 ETA 중 도보+준비시간을 충족하는 차량만 추천한다. 없으면 `다음 차량 정보 확인 필요`를 표시한다. 다음 차량 상태에서는 카드의 ETA도 실제 추천한 **다음 버스/열차**로 맞추고, 현재 차량의 부족 시간은 별도로 표시한다.

지도 탭과 경로 탭은 같은 Compose 호출 위치·이동 세션을 사용한다. 탭 값은 조회 효과 키에 넣지 않았다. 지도는 최초 사용 때 생성하고 두 탭 사이에서는 같은 MapView를 유지한다. 기존 실제 경로 좌표, 파랑/초록 경로, 마커, 확대·축소·현재 위치·카메라 인자는 유지했다. 다른 하단 기능 화면의 기존 생명주기는 유지한다. 경로 미선택 시 `경로를 먼저 선택해 주세요`를 표시한다.

## 5. 실제 진동 30초 제한 검증

- 실제 Android 진동 호출 직전의 공통 가드가 `SystemClock.elapsedRealtime()`을 사용한다. 진동 API가 예외 없이 호출된 때만 성공으로 기록한다. 물리적으로 진동했는지 센서로 측정한 것은 아니다.
- 첫 안내 상태 설정은 무진동. 이후 변경 상태가 두 차례 관측되고 3초 이상 유지돼야 상태 변경 진동 대상이 된다. UI 문구에는 이 3초를 적용하지 않는다.
- 여유/도보 1회, 주의/RUN 2회, 다음 차량 상태 3회, UNKNOWN 0회. 1회 100ms, 사이 간격 150ms.
- 마지막 실제 호출 후 10초·29.9초·29.999초 호출은 차단, 30초 호출은 허용하는 가드 테스트 통과. UI/서비스를 번갈아 호출해도 동일 제한이다.
- 긴급도 상승도 차단하며 차단된 이벤트는 소비한다. 시각만 지났다고 재생하지 않는다. 새로 확정되는 상태 변경이 필요하다. 동일 상태 반복/초기 상태/진동 설정 OFF에서는 반복 진동하지 않는다.
- 실제 진동 함수와 Robolectric Vibrator 연결 테스트도 통과했다. 휴대폰 모터 체감 테스트는 미실시다.

## 6. 도보 30초 계산 및 기존 값 유지 검증

GPS 수신은 약 4초 그대로 유지하고 계산 타이머를 분리했다. 경로 API는 모든 GPS마다 호출하지 않으며 최소 30초 간격과 기존 유의미한 이동·이탈·90초 경로 재조회 조건을 사용한다. 느린 요청 시간까지 고려해 다음 루프의 시작 간격을 계산한다. 동일 프로세스의 화면→서비스 시작에서도 추적기와 마지막 요청시각을 넘겨 즉시 중복 요청을 줄인다.

모의 경로 `430m/360초`에서 20초 경과·유효 GPS 이동 중에도 기존 계산값을 유지하고, 30초 시점에는 실제 경로 진행도로 더 짧은 거리·시간으로 교체했다. 설정/GPS 보정속도는 해당 계산 시각 값과 함께 보관한다. 신규 유효 경로 응답은 즉시 반영하며, 실제 뒤로 걸어 이전 거리보다 멀어진 것이 확인되면 30초를 기다리지 않고 안전하게 재계산한다.

갱신 간격으로 수명을 늘리지 않는다: 기존 GPS 30초/경로 120초 한도 및 더 짧은 개별 유효기간 유지. API 실패·일시적 부정확 GPS는 그 안의 근거만 보존한다. 실제 경로 이탈/권한 상실/선택 변경/만료는 무효화한다. 정지 중 시간 경과만으로 거리가 감소하지 않는다.
