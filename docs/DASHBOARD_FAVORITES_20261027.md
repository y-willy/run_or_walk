# run_or_walk 대시보드·자주 타는 버스 구현

## 기준과 범위

- 기준 main: `c1c2d47` (PR #5에 이전 기능 브랜치가 이미 병합되어 있었음).
- 작업 브랜치: `feature/dashboard-favorite-buses`.
- 기존 걷기 분석·실시간 판단·조용한 새로고침·차등 진동도 유지했다.
- 이번 첨부에는 참고 이미지 파일이 없었다. 요청서의 밝은 카드, 여백, 상태 색상, 파랑/보라 보조색, 하단 탭 설명을 디자인 기준으로 사용했다.
- AI 예측·확률·시뮬레이션·로그인·새 서버·외부 API·라이브러리를 추가하지 않았다. 앱 표시 이름은 `run_or_walk`다.
- main 병합 및 Worker 배포는 하지 않았다.

## UI 변경 전후

기존 상단 두 모드 선택과 남색 안내 카드 중심 화면을, 하단 4개 탭과 이동 대시보드로 바꿨다. 기존 검색/승차 선택/지도는 기존 화면 상태와 콜백을 그대로 사용한다.

- 하단: 경로 찾기 / 정류장 찾기 / 자주 타는 버스 / 설정. 좁은 화면이나 큰 글꼴에서는 짧은 탭 이름을 표시하고 접근성 이름은 전체 이름을 유지한다.
- 헤더: 기존 브랜드 로고, `run_or_walk`, 선택한 교통수단·노선·승차점·방향, 기존 설정 진입.
- 현재 이동속도와 승차점까지 남은 거리 카드. 속도는 유효한 실제 GPS 속도/속도 정확도만 표시하고, 설정한 보행 속도를 현재 측정값으로 표시하지 않는다.
- 안내 카드: 기존 WALK는 초록, 현재 코드에서 ‘뛰세요’로 표시하는 FAST_WALK/RUN 대응은 빨강, NEXT_VEHICLE은 파랑, UNKNOWN은 회색이다. 새로운 빠른 걸음/달리기 상태나 계산 규칙을 만들지 않았다.
- 비교 영역: 실제 차량 ETA, 도보 기준 도착 시각, 여유시간을 포함한 차이와 진행도. 공식 실시간 / 위치+공식 시간표 추정 / 공식 시간표 예정을 구분한다. 확률·안전도는 표시하지 않는다.
- 지도 기본 펼침, 펼치기/줄이기, 기존 두 색상 경로, 마커, GPS 이동 및 확대·축소 코드 유지.
- 라이트·다크 테마와 320dp·글자 130%에서 컴포넌트를 렌더링해 확인했다. 좁은 수치 카드는 세로로 배치하고 즐겨찾기 버튼은 공간이 부족하면 다음 줄로 흐른다.

## 자주 타는 버스

기존 프로젝트에는 DataStore/Room이 없어 작은 공식 선택 목록을 SharedPreferences에 저장한다. ETA·GPS·인증키는 저장하지 않는다. 최대 50개이며 즐겨찾기는 공식 제공기관+정류소 ID+노선 ID+승차 순서로 구분한다. 노선명/표시 이름이 달라져도 같은 공식 ID의 중복 항목을 만들지 않는다.

저장하는 선택 모델은 기존 JourneyMonitoringRequest와 그 검증 codec을 재사용한다. 서울은 ARS·stopId·routeId·stopOrder·routeType·방향을, 경기는 stationId·routeId·staOrder·노선명·행선지·승차 좌표를 함께 보존한다. 잘못된 제공기관 조합과 불완전한 ID는 저장/복원에서 제외한다.

정상적으로 연결된 버스 선택에 ☆/★ 등록·해제를 제공한다. 목록에서 삭제, 위로 이동, 사용자 표시 이름 변경을 지원하고 앱 재실행 후에도 유지한다.

카드가 실제로 화면에 나타나면 기존 서울/경기 Repository로 공식 도착정보를 한 번 조회한다. 메타데이터에서 저장된 정확한 노선 ID와 승차 순서를 먼저 확인한다. 다른 방향이나 다른 노선으로 대체하지 않는다. 연결이 폐기/변경되면 재선택 문구를 표시한다. 공식 ETA가 없는 경우 예시 숫자를 표시하지 않는다. 조회 제한, 인증/연결 오류, 유효한 ETA 없음과 재선택 필요 상태를 구분한다.

한 화면 진입 중 경기의 동일 정류소 응답은 30초간 공유한다. 서울은 기존 Repository 캐시와 제한 처리를 재사용한다. 카드의 카운트다운은 로컬에서 갱신하지만 API를 주기적으로 폴링하지 않는다. 화면 이탈/앱 백그라운드 전환 시 카드 조회 Coroutine이 취소된다. 수동 갱신도 기존 backoff를 따른다.

‘이 버스로 이동 안내’를 선택하면 검증한 공식 선택만 정류장 찾기에 복원한다. 이전 목적지/도보/GPS/ETA는 가져오지 않으며 기존 위치 조회·도보 경로·공식 ETA·자동 판단 효과가 새로 수행된다. 다른 경로의 백그라운드 안내는 종료하고, 새로운 화면에서 기존 이동 안내 시작 버튼을 사용할 수 있다. 경기 즐겨찾기에서 직접 복원한 선택도 기존 세션 저장과 호환된다.

## 검증 범위

실행 명령:

```bash
bash gradlew :app:compileDebugKotlin :app:testDebugUnitTest :app:assembleDebug \
  --init-script /workspace/.cloud-setup/timetable-verification.gradle
```

추가 init script는 기존 클라우드 회귀 fixture 105개를 실행하는 환경 전용 파일이다. 다른 PC에서는 init script 없이 저장소의 테스트 66개를 실행할 수 있다. 기존 버스/지하철/공식 시간표/위치/백그라운드/진동 및 새로고침 회귀와 새 즐겨찾기·UI 테스트를 함께 실행했다.

UI 이미지와 즐겨찾기 API 테스트는 모의 데이터/저장된 공식 JSON을 사용한 검증이다. 새 운영 API를 실시간으로 확인하거나 실제 휴대폰의 지도 SDK를 실행한 것으로 보고하지 않는다. APK에는 테스트 화면의 숫자가 들어가지 않는다.

## 실기기에서 추가 확인할 사항

- 서울/경기 실제 정류소에서 즐겨찾기 등록 후 공식 API 응답·방향·GPS 도보 경로·판단이 연결되는지.
- 운영 API 제한/미운행/폐기 정류소 상태와 네트워크 복구.
- 실제 카카오 지도 마커·경로·확대축소와 탭 전환 후 지도 재개.
- 화면 꺼짐 모니터링·차등 진동·제조사 절전 정책.
- 앱 강제 종료/재실행 후 목록·별칭·순서 및 선택 복원.

Worker와 판단 계산기·센서·서비스 알고리즘·공식 API 계약은 변경하지 않았다. 새 APK 설치가 필요하며 Worker 재배포는 필요하지 않다.
