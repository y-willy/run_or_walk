# HTTPS 지하철 중계 서버

> 이전 Python 서버 대안입니다. 현재 Android 앱은 Cloudflare Worker의 `/health`, `/subway`를 사용합니다. 현재 배포는 [Cloudflare 안내](../docs/CLOUDFLARE_WORKERS_NOTES.md)를 따르세요.

사용자가 선택한 HTTPS 중계 방식의 배포 코드다. 아직 공개 서버·도메인·서울 전용 인증키가 없어 배포하지 않았다. 앱은 공식 키를 갖지 않고 이 서버를 HTTPS로 호출한다.

필요한 것:

- Docker와 Compose가 설치된 서버, 서버를 가리키는 DNS 호스트명, 외부 80/443 포트.
- [서울시 실시간 지하철 전용 인증키](https://data.seoul.go.kr/together/guide/useGuide.do). Kakao 키로 대체할 수 없다.
- 서버와 앱이 공유할 32자 이상의 공백 없는 무작위 접근 토큰. 비밀값 관리 도구로 만들고 안전하게 전달한다.

## 배포

서버에서 저장소를 받아 다음을 실행한다.

```bash
cd gateway
cp .env.example .env
# 서버의 비밀값 관리 도구/편집기로 .env의 도메인, 전용 키, 접근 토큰을 채운다.
# .env는 Git에서 제외되며 값이 있는 상태로 공유하지 않는다.
docker compose up -d --build
```

Caddy가 설정한 DNS 호스트에 HTTPS 인증서를 발급·갱신한다. 실제 DNS와 80/443 접근이 있어야 발급된다. 단순히 컨테이너가 시작됐다는 이유로 HTTPS 연결이 준비됐다고 간주하면 안 된다.

준비 확인: `https://실제도메인/healthz`의 HTTP 200 및 `{"status":"ready"}`. 인증서 검증을 끄지 않는다. 그다음 인증된 `/v1/subway/arrivals?stationName=서울` 호출에서 실제 공식 데이터 또는 정상적인 빈 결과를 확인한다. 인증 헤더·전용 키·요청 전체를 로그나 이슈에 붙이지 않는다. 경기도 지원 여부는 대상 역·호선별로 추가 확인한다.

앱 개발 PC의 **Git에서 제외된** `local.properties`에 다음 이름으로 설정한 뒤 APK를 다시 빌드한다. 아래 주소는 설명용이며 실제 서버로 대체해야 한다.

```properties
SUBWAY_GATEWAY_URL=https://subway.example.com
SUBWAY_GATEWAY_TOKEN=
```

접근 토큰은 서버 `.env`의 `SUBWAY_GATEWAY_TOKEN`과 같은 값이다. **`SEOUL_SUBWAY_API_KEY`는 서버에만 두고 앱 설정에 추가하지 않는다.** 앱은 HTTPS, 정상 인증서, 리다이렉트 없는 중계 응답만 사용하며 직접 HTTP 호출을 허용하지 않는다. 서버가 없거나 설정이 비어 있으면 자동 판단은 UNKNOWN이다.

## 보안·호출량·운영 한계

- 공식 TOPIS 문서의 상류 주소는 HTTP다. 휴대폰↔중계 서버는 HTTPS이며, **중계 서버↔TOPIS까지 전 구간 HTTPS라고 주장하지 않는다.** 공식 HTTPS 주소가 확인되면 상류만 교체할 수 있다. TLS 검증을 해제하는 코드는 없다.
- 상류 호스트는 코드에 고정돼 있으며 입력 URL을 전달받지 않는다. 요청 역명은 공식 목록의 정확한 이름만 허용한다.
- 서버는 30초 캐시, 실패 캐시, 전역 최소 1초 요청 간격, 기본 900회/일(KST)의 영속 SQLite 제한을 사용한다. 공식 기본 한도는 1,000회/일이며 다른 앱에서 같은 키를 쓰는 사용량까지 이 서버가 계산할 수는 없다. 제공기관의 실제 한도 초기화 시각을 보장하는 정책도 아니다.
- 반환되는 필드는 도착정보 허용 목록뿐이다. API 키·개발자 원문 오류·상류 URL은 전송하거나 로그에 남기지 않는다. 날짜는 원래 생성 시각 그대로 전달한다.
- 앱용 공유 토큰은 사용자별 인증 체계가 아니다. 배포 APK에서 추출 가능하므로 대규모 공개 서비스에는 사용자 인증·운영 모니터링 등 추가 설계가 필요하다. 작은 비공개 테스트 배포와 호출량 제한을 전제로 한 최소 중계 구현이다.
- 서버를 여러 복제본으로 확장하면 캐시·호출량 제한을 중앙화해야 한다. 현재 Compose는 한 복제본이다. Caddy 저장 볼륨과 요청량 DB 볼륨은 재시작 후 유지된다.

## 로컬 운영 확인

설정 없이 로컬 프로세스를 시작하면 `/healthz`는 503 `configuration_required`를 반환한다. 실제 공개 DNS·인증서 발급·전용 키 인증은 별도로 확인해야 한다.
